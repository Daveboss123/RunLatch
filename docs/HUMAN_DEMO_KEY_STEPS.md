# Your next step — local demo keys

The website is deployed at **https://runlatch.vercel.app**. GitHub source remains private. Real NEAR execution needs the following human-only local step first.

## Run this in your own terminal

Open **Windows Terminal → PowerShell**, not an agent-run shell. No administrator mode or execution-policy change is required.

```powershell
cd 'C:\Users\David\RunLatch'
node scripts/setup/human-demo-keys.ts --probe
```

Expected result:

```json
{"status":"STORE_READY_NONSECRET_PROBE","human_keys_created":false,"network_calls":0}
```

The probe writes/verifies/deletes only one new nonsensitive Windows Credential Manager entry. It does not generate keys or inspect existing credentials.

Then run:

```powershell
node scripts/setup/human-demo-keys.ts
```

The command displays these exact proposed roles:

- Operator: `runlatch-demo-1108.testnet`
- Contract: `gate.runlatch-demo-1108.testnet`
- Provider: `db.runlatch-demo-1108.testnet`
- Agent recovery and separate restricted agent key: `agent.runlatch-demo-1108.testnet`

At the prompt, type:

```text
CREATE LOCAL DEMO KEYS
```

Any other response cancels without generating keys. This approves **local generation only**, not account creation, transactions or deployment.

## What it does

Creates five Ed25519 key pairs in your local human process and writes their private values directly to **Windows Credential Manager** for your Windows user. The native store round-trip is checked before `STORED_VERIFIED` is printed. No private-key file, clipboard, environment injection, PowerShell script, remote call, account creation or signature is used. The pinned native tool is under ignored `.tools/`; it is not in the web app.

It prints public records with `role`, `account_id`, `public_key`, `credential_target` and `status`. **Send only the five lines with `"status":"STORED_VERIFIED"` back to the agent.** They contain no private keys. Do not export Credential Manager values, paste recovery phrases or send private-key data.

Expected final line:

```text
LOCAL_KEYS_READY: send only the five STORED_VERIFIED public records. No accounts created or signed.
```

If the command stops, **do not rerun it automatically**. Keep any public `STORE_ATTEMPT`/`STORED_VERIFIED` lines and send those plus the static failure message. A partial or unknown store result must be checked, not replaced with another set of keys.

## After the public keys

The agent will fill the [exact account/deployment package](DEMO_ACCOUNT_PACKAGE.md) with your public keys, current chain values, complete arguments and the verified contract hash. Review the final package before any public creation/signature. You run human owner/provider/contract signing locally; the app/agent never receives those private keys. The separate restricted agent key will later be admitted only for the exact approved contract/method/gas allowance and requests.

This key command is a tested setup handoff, **not a completed testnet MVP**. Actual account creation, deployment, native transfer/private callback, fixture check and your explicit acceptance still need execution/evidence.

## Verification and limits

Five focused Node tests cover role separation, generated NEAR key representation against Node Ed25519 verification, noninteractive refusal, source/no-fallback checks and an actual nonsensitive native Windows storage probe. Typecheck and targeted lint pass. The native test explicitly skips on non-Windows hosts or fresh checkouts without the ignored native tool; the local five-test result has no skips. No real human keys were generated by the agent or persisted in tests. Buffer clearing is best effort; managed strings/OS memory are not guaranteed erased. Windows Credential Manager does not protect against malicious software running as the same Windows user, and its API lacks an atomic create-only operation; random-key targets are checked for existing entries but this is not a same-user race defence.

On a different Windows x64 checkout the private local tool must first be installed with scripts disabled:

```powershell
npm.cmd install --prefix '.tools/human-credential-store-3.3.7' --no-save --package-lock=false --ignore-scripts --omit=dev --no-audit --no-fund koffi@3.3.7 @koromix/koffi-win32-x64@3.3.7
```

It is already installed on this computer. The helper checks the reviewed native binary's size/SHA256 before loading and refuses changed or missing tools; it never downloads, compiles or switches a binary itself.
