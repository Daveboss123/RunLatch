# Restricted process-key injection — local groundwork

**8 November 2026. No public signing or Working testnet MVP completion.** This Node-only module consumes one explicitly injected key slot and tests it through the existing LOCAL exact-review/journal/key-guard path. All material used in verification was generated ephemerally in memory; no real credentials were read or used.

## Supported input and boundary

`consumeRestrictedProcessKey(target, scope, environment)` requires the existing explicit testnet target and restricted-agent scope. There is no default `process.env` read, CLI, file loader, keystore search, wallet connector or network action. A future approved local entry point must pass its own process environment explicitly; none exists yet.

The sole slot is `RUNLATCH_AGENT_PRIVATE_KEY`: exactly64canonical base64url characters encoding Node's48-byte unencrypted Ed25519 PKCS#8 DER. This is **not** the raw `ed25519:...` secret format used by NEAR wallets/CLI. Raw seeds, recovery phrases, PEM/JWK, encryption/passphrases, other algorithms, alternative encodings and automatic conversion are unsupported. No new credential-generation/conversion workflow is enabled. Never put real material in chat, shell arguments, `.env`, files, logs or public examples; any future approved injection must happen privately through the approved OS/process mechanism.

Public config is validated before touching the slot. The loader requires an own removable/writable data property, rejects proxies/accessors/inherited/frozen inputs without executing their getters, and never enumerates unrelated environment values. It removes the slot synchronously **before** decoding/importing. Invalid key material stays removed; no retry, restore, alternate variable or broader-key fallback exists. Invalid public config, duplicate identity or the process-wide load limit are rejected before reading/removing the unused slot; that unused input remains the caller's responsibility.

Node `createPrivateKey({format:'der',type:'pkcs8'})` parses the bytes. The type must be Ed25519; a canonical Node re-export must equal those bytes; the public key derived with `createPublicKey(privateKey)` must equal the pinned agent public key. Temporary decoded/re-exported buffers are filled with zero in `finally`. Errors contain stable codes only, never underlying crypto messages/input fragments/causes. No handwritten ASN.1/Ed25519 implementation or new dependency is used.

Returned frozen handles expose public target/scope/key and an explicit limitation only; private KeyObjects stay in a WeakMap. A process may load at most64distinct `(testnet,agent account,public key)` identities, and cannot reload an identity after disposal or against another target. This local bound prevents unbounded bookkeeping, not a multi-account product. Disposal is idempotent and drops the stored key/signer references; adapters already handed out then fail before any new signature. No key/request/nonce claim is released or reset.

## Shared LOCAL signing, not a second payment path

The former ephemeral `signReview` implementation now lives in `local-review-signer.ts`. `local-signing-exercise.ts` still generates an in-memory ephemeral key and exposes the same labels/behavior. `createInjectedLocalSigningExercise(handle)` uses that **same** implementation with additional exact target/agent/public key/recovery key/allowance-cap binding. Multiple adapters for one handle share the consumed-request set. The runner takes its minimal existing `signReview` port rather than require the ephemeral source label.

Both paths retain issued original/fresh exact review checks, expiry/cancellation, ordinary submit-only access/recovery/positive finite allowance, decimal nonce+1, one zero-deposit V0 action, exact byte/hash/signature verification, detached signed-byte output and consumed-request refusal. **HTTP-labelled reviews and owner approvals still fail with `PUBLIC_SIGNING_NOT_ADMITTED`.** A prepared signature proves no inclusion, settlement, provisioning or authority. The original journal/one-shot anchor/sequential coordinator/broadcast seam remain unchanged; unknown output never unlocks/resends the original request.

Public-key equality cannot distinguish a full-access key from a function-call key: permissions are separate on-chain state. The pinned scope is not installation/readback evidence or human consent. No public runner is admitted until exact scoped public reads, sequential final reconciliation, a bounded transport and separately approved human account/action/gas/funding scope are connected. Rust remains the Gate; this loader does not evaluate business policy, mutate funds or install/delete on-chain keys.

## Security and privacy limits

- JavaScript strings, native crypto memory, caller-retained copies, environment snapshots, crash dumps, debuggers and OS process inspection cannot be proven erased by dropping references or zeroing temporary buffers. No secure-memory/custody guarantee is claimed.
- Environment deletion affects this process, not a parent process, previously spawned workers/children or another shell. Node documentation also notes Windows case-insensitive main-thread environment names and case-sensitive worker copies. A generated child-process test proves only that **a subsequently spawned child** did not inherit the removed test slot. Do not spawn children/workers while real key material is still present.
- Trusted Node code can import built-ins and bypass application restrictions. Opaque handles, issued reviews and file claims are not an OS sandbox against a malicious process/operator. No real secret is exposed to the coding assistant in these tests.
- Browser imports/routes/build are unchanged. There is no public shared-key endpoint or default upload/telemetry/paid inference.
