The already installed, checksum-locked Linux `near-api-types0.8.7` transaction/action/public-key/signature types and `near-openapi-types0.8.0` signed wire wrapper were also inspected. Their V1 representation differs from the current JS SDK; **V1/gas-key lanes/priority fees are not supported**. V0 agreement does not establish whole-SDK compatibility.

Admitted V0 layout is Borsh: signer string, Ed25519 public-key tag0 and32bytes, u64 nonce, receiver string,32-byte block hash, one-element action vector, FunctionCall tag2, method string, byte-vector arguments, u64 gas and u128 zero deposit. V0 has **no transaction enum prefix**. The transaction hash/signing preimage is SHA-256 of the unsigned V0 bytes; a signed envelope appends Ed25519 signature tag0 and64bytes. It is not the hash of the signature-bearing envelope. Node's built-in SHA-256/Ed25519 implementation is used; no new cryptographic algorithm or handwritten DER is introduced.

## Modules and boundaries

- `scripts/near/base58.ts`: strictly32-byte **public** key/hash conversion only, including leading zeros, canonical re-encoding and256-bit bounds. No secret parser or arbitrary-length base58 API.
- `scripts/near/transaction-codec.ts`: exact `testnet` envelope, named distinct signer/receiver, `submit_purchase`, existing strict proposal, positive decimal-string nonce/gas≤300Tgas and **zero deposit**. Rejects owner/admin methods, arbitrary action lists, transfers/deploy/key actions, mainnet, extra fields, unsupported keys and malformed input. It is a serializer, **not** a Gate or authorization decision. The public transaction format itself does not embed network identity; account suffix/target checks do not replace approved network scope.
- Canonical JSON argument bytes reuse existing bounded review-content encoding; this is not the Rust policy/quote/request hash. Decoder rejects truncation, unsupported tags/counts, oversized strings, invalid UTF-8, duplicate fields, trailing/signed data and semantically equivalent noncanonical argument bytes. Unsigned wire≤8KiB, arguments≤4KiB. Nonces/revisions remain strings/u64, not financial `Number` casts; conversions to Number are bounded byte values/lengths only.
- `scripts/near/signature-envelope.ts`: accepts **public signature bytes only**, imports a public Ed25519 JWK through Node, verifies the exact unsigned hash and reconstructs/inspects the restricted signed envelope≤8257bytes. Invalid/wrong-key/wrong-hash/changed-action signatures fail closed. A valid signature alone is not proof of access-key permissions, project authority, human consent, network execution or settlement. No secret/signing callback, URL or broadcast port exists here.
- `scripts/near/local-signing-exercise.ts`: generates its own **ephemeral in-memory test key**, never imports/exports a private key. Only injected-test-source, issued original/fresh exact purchase reviews can be signed; HTTP-labelled reviews and owner approvals are refused. Public key must match the declared restricted access/policy; gas allowance/recovery scope and original/fresh expiry are retained. Ordinary nonce+1 and reviewed block hash are fixed before signing. One signature per contract/capsule/request per helper; a failure after consumption never resets it. This is a test exercise, **not** process-injected public agent execution or proof that a public account registered the key.
- The local helper signs only with built-in Node Ed25519, verifies and re-inspects its wire bytes, and returns exact public observation intent. Existing `exerciseSingleAttempt` remains unchanged: exclusive request claim precedes preparation, identity/entry markers are durable before one offline invocation, unknown results retain the same identity and block retry. Signed bytes/keys never enter the journal; a returned result never supplies settlement evidence. The helper alone is not a durable cross-process nonce allocator. Public execution needs a separate admitted signer/key-loader, per-key concurrency strategy and approved target/action scope.

All input DTOs are detached/frozen; every returned wire view is a fresh copy. Modules live outside `src`; current source-import search finds no browser dependency on them. No package/lockfile/contract/frontend change was needed. This static separation is **not** a new production browser build/bundle scan or release proof.
